# Breast-Cancer-Classification-Pipeline

## Overview

This repository implements a professional machine learning workflow to classify breast mass nuclei as **Malignant** or **Benign**. It documents the transition from **Manual Research** (understanding math and safety thresholds) to **Production Engineering** (building automated, scalable pipelines).

---

## Dataset & Universal Preprocessing

Before any modeling began, the raw data underwent a rigorous cleaning process to ensure mathematical integrity:

* **Artifact Removal:** Dropped the `id` column and the `Unnamed: 32` artifact (a common CSV parsing error containing null values).
* **Target Encoding:** Mapped categorical `diagnosis` (**M** and **B**) to integers (**1** for Malignant, **0** for Benign).
* **Feature Scaling:** Since SVM and Logistic Regression rely on distance, I applied `StandardScaler` to ensure features with large ranges (like `area`) don't dominate those with small ranges (like `smoothness`).

---

## Phase 1: Experimental Research (`breast_cancer_svm.ipynb`)

This stage focused on mastering model behavior, identifying risks like overfitting, and engineering for medical safety.

### **Execution Steps in Order:**

1. **Correlation Analysis:** Generated a heatmap to detect multi-collinearity, identifying that `radius`, `perimeter`, and `area` are nearly 100% correlated.
2. **Manual SVM Tuning:** Iterated through **RBF** and **Linear** kernels, manually adjusting **C** and **Gamma** parameters.
3. **Overfitting Check:** Compared **Training Accuracy** (~98%) against **Test Accuracy** (~97%). The minimal gap confirmed the model generalized well rather than memorizing the data.
4. **Threshold Engineering (Medical Safety):** * **The Problem:** Standard models use a 0.5 threshold, which may miss "borderline" cancer cases (False Negatives).
* **The Solution:** I manually lowered the decision threshold to **0.30**. This makes the model "more sensitive," ensuring fewer malignant cases are missed.



---

## Phase 2: Production Engineering (`breast_cancer_pipeline.ipynb`)

This stage converted research findings into a scalable software system.

### **Pipeline Steps in Execution Order:**

1. **Logging Configuration:** Initialized a `logging` framework to track data flow and timestamps in real-time.
2. **Robust Data Ingestion:** Built a `load_data` function that handles local CSV files with an automated fallback to built-in datasets.
3. **Automated Preprocessing:** Constructed a Scikit-Learn `Pipeline` containing:
* **IterativeImputer:** Handling missing values via multivariate regression.
* **StandardScaler:** Ensuring uniform feature scaling.
* **SelectKBest:** Automatically selecting the top 15 features using ANOVA F-values to reduce noise.
4. **Algorithm Tournament (GridSearchCV):** A cross-validated competition between **SVM, Random Forest, Gradient Boosting,** and **Logistic Regression**.
5. **Model Serialization:** The winning model is exported as `best_model.joblib`.

## How to Test the Inference

To verify the system's performance on new data, the inference process requires two key components:

The Trained Model: Ensure best_model.joblib is present in your project directory (this is the "brain" generated by the pipeline).

The Source Dataset: Ensure breast_cancer.csv is available in the folder. The inference script uses this file to extract random, real-world samples to simulate a "live" diagnostic scenario.

Execution:
Once both files are in place, run the final cells in the Pipeline notebook (breast_cancer_pipeline.ipynb). The script will:

Load the saved .joblib model.

Extract 5 random samples from the dataset.

Generate malignancy probabilities and display a side-by-side comparison against the actual medical ground truth.
